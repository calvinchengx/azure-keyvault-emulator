# azure-keyvault-emulator v0.4.0

The full-parity release: every implementable gap against real Azure Key Vault
is closed, and every green claim is witnessed by an unmodified Microsoft SDK.
This is also the release where the project changed its ground truth — Microsoft
docs and SDKs are now the sole reference, and the parity ledger enforces in CI
that **every 🟢 claim names its witness**.

## The witness matrix

Real `azure-keyvault-*` clients for **Python, JavaScript and .NET** run in CI
against the emulator pair (entra issues, this vault validates), alongside the
existing Go suite — three OSes each. These are Microsoft's bits, not mocks:
a divergence from real Key Vault fails a suite even when our own tests agree
with our own code.

## Keys

- **BYOK for real**: `CKM_RSA_AES_KEY_WRAP` import — RSA-OAEP-SHA1 unwraps the
  ephemeral AES key, RFC 5649 AES-KWP unwraps the target key. A real
  `azure keyvault key import` BYOK blob round-trips.
- **Rotation**: the `rotate` endpoint, rotation policies (ISO-8601 windows),
  and clock-driven **auto-rotation** — advance the emulator clock and versions
  mint themselves.
- **`key_ops` enforced** on every crypto operation; **`nbf`/`exp` enforced**
  (an expired key is refused for crypto, exactly as real KV refuses it).
- **`exportable` + `release_policy`**: export is gated on the policy, and a
  policy-bearing key demands `exportable`, both ways round.
- **oct/BYOK-to-vault refused faithfully** — oct keys are a Managed HSM
  feature and the vault says so, byte-shaped like Azure's refusal.

## Certificates

- **Issuer registry drives issuance** (self-signed vs CA-shaped chains).
- Operation **cancel and delete**; **delete cascades** to the linked key and
  secret, as in Azure.
- Create reports **`inProgress` then `completed`** across polls — the LRO
  shape MSAL-era SDK pollers actually require (the Python SDK's poller hung
  on anything less).

## Vault semantics

- **Access policies and RBAC built-in roles** (real Azure role GUIDs) compile
  onto the authorization allowlist, with the RBAC/access-policy either-or real
  vaults enforce.
- **Object-scoped authorization** — permissions can name a single secret/key/
  certificate, not just a type.
- **Purge protection**: purge refused with `403`, `recoveryLevel:
  "Recoverable"` reported.
- **Multi-issuer trust**: a comma-separated issuer list, each validated
  against its own JWKS.

## Behavior changes to know about

- **Backup blobs are now opaque, sealed AEAD envelopes** (as real KV's are).
  Backups taken with earlier releases do not restore into v0.4.0.
- **`api-version` is validated** — requests carrying versions Key Vault never
  shipped are refused with the Azure-shaped error instead of being ignored.
- The **james-azure-keyvault-emulator reference is gone**; parity claims trace
  to Microsoft documentation and SDK behavior only.
