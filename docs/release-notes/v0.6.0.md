# v0.6.0

**ARM governs this vault by default.** Role assignments and the vault resource
decide who may do what, and no assignment means no access — as in Azure, where
a Key Vault without an ARM resource behind it is not a thing you can have.

Until now that was opt-in behind `-arm-url`, and the default was an allowlist
that permitted everything when empty. Azure has no such state. Reversing it
also removes configuration rather than adding it: the stack that already
starts entra now starts arm too, and seeds the grant Azure gives the principal
that creates a vault, so the first request works.

One breaking change, called out first.

---

## Breaking: the compose stack denies by default

`docker compose up` (and `make up`) now start **arm-emulator** alongside entra,
point the vault at it, and seed:

- the `Microsoft.KeyVault/vaults` resource, and
- a **Key Vault Secrets Officer** assignment for the principal that created it.

If you relied on the previous behaviour — every authenticated caller allowed —
that is now reachable only by asking for it:

```bash
KV_ARM_URL= docker compose up     # or: make up NOARM=1
```

**The binary is unchanged.** `-arm-url` still defaults to empty, so
`go install` users and anyone driving the emulator directly see no difference.
This release changes what the *stack* does, not what the process does — a
single binary cannot start ARM for you, and pretending otherwise would mean
either denying everything or silently falling back to permissive.

`docker-compose.arm.yml` is removed; its contents are in the base file.
`make up ARM=1` becomes `make up`, and `NOARM=1` is the opt-out.

## Why seed at all

ARM's rule is no-assignment-means-no-access. Wiring ARM in without seeding
would produce a stack whose very first request is a `403` and whose fix is to
hand-write a role assignment against the right scope and object id — strictly
more configuration than before, which is the opposite of the point.

Azure does the same thing: create a vault in the portal and the creating
principal has access to it. The seed is `scripts/seed-arm.py`, deliberately
plain and readable — it is also the documentation for doing this by hand
against a real vault.

## Pinning

`arm-emulator`'s image is pinned to the BOM (`0.2.0`) rather than `:latest`.
It was the last family image in this repo still tracking newest, and it was
invisible to the family pin gate because it uses `ARM_IMAGE_TAG` — the image
tag drops the `v` that the Go module version carries, so the two deliberately
have different variable names.

## Parity

The authorization rows are rewritten to match. Data-plane authorization is
now **🟢 Real** — ARM's wire, real assignments, default-deny — with the
allowlist described as what stands in *when you opt out*. The permissive-empty
posture is still documented, but as a deliberate escape hatch rather than the
default, and it now says plainly that Azure has no equivalent of it.

## Upgrading

If you use the compose stack and depended on unrestricted access, add
`KV_ARM_URL=` or `NOARM=1`. If you run the binary directly, nothing changes.
The stack now pulls `ghcr.io/calvinchengx/arm-emulator:0.2.0`, so an offline
`docker compose up` needs that image present.
