# v0.5.0

Twenty-five commits with one theme: **authorization stops being this process's
opinion and becomes ARM's.** Role assignments and access policies written over
ARM's real wire now govern the data plane, group membership resolves, and the
vault's own configuration — purge protection, the soft-delete window — comes
from the `Microsoft.KeyVault/vaults` resource rather than from flags. The real
`az` CLI drives the whole thing as a registered cloud, and is credited as a
witness for it.

No breaking changes. ARM governance is opt-in: without `-arm-url` nothing
changes.

---

## ARM governs the data plane

- **Assignments and access policies decide access.** With `-arm-url` set, role
  assignments and vault access policies written over ARM's real wire drive the
  allowlist — and **no assignment means no access**, as in Azure. The
  authorization parity rows turn green on the arm-chain witness rather than on
  assertion.
- **Group membership resolves.** A role assigned to a group authorizes any
  caller carrying that group in its token. Proven end to end: Alice reaches the
  vault through Engineering without ever being named.
- **Vault configuration comes from ARM.** Purge protection and the soft-delete
  retention window are properties of the ARM resource in Azure, so when ARM
  governs they are read from there instead of this process's flags. An absent
  vault resource changes nothing, so existing setups are unaffected.
- `enableSoftDelete` is parsed but deliberately not applied — the docs now say
  why, rather than leaving a reader to infer it from silence.

## The real az CLI as a witness

`az cloud register` → login → resource group → vault → role assignment →
`set-policy`, with the data plane's **403-to-authorized flip asserted after
each step**. It runs as a CI job, so the claim that the family behaves like a
sovereign cloud is tested rather than described.

## Runnable

- **The image's `/data` is writable by the nonroot uid it runs as.** It was
  owned by root, so a fresh volume mounted there left the server unable to open
  its SQLite file and the container exited 1 before serving anything.
  Distroless has no shell, so the directory is created in the build stage and
  copied in with the right ownership.
- **Compose brings up the trio**, so `make up` gives the whole authorization
  story; ARM moved into an overlay so the base file stays the minimal pair.
- **Peer images are pinned to the family BOM**, not `:latest`. Tracking
  `:latest` is how an upstream release reaches CI unannounced; drift testing
  still works by overriding the variable.

## Security and supply chain

- **CodeQL and Dependabot**, the last repo in the family without them. Ten
  findings are fixed here: nine workflows running with an unrestricted
  `GITHUB_TOKEN`, and an RSA key size that was validated in a guard and then
  passed as a variable, so the 2048-bit floor was invisible to analysis. The
  sizes are literals now — same accepted set, floor visible at the call site.
- A docs-generator sanitizer escaped quotes but not backslashes, emitting
  frontmatter that would not parse for any title containing one.
- Eight grouped dependency updates, including two majors.

## Upgrading

Nothing to do. ARM governance activates only with `-arm-url`; leave it unset
and this release behaves as v0.4.0 did. If you do point it at an
`arm-emulator`, use **v0.2.0 or later** — its tenant and subscription GUIDs
changed, and the two must agree.
